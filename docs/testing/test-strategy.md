# Тестілеу стратегиясы — Shop-Inventory

## 1. Тестілеу деңгейлері мен автоматтандыру көлемі

| Деңгей | Құрал | Не тексереді? | Автоматтандыру көлемі |
|---|---|---|---|
| **Unit (Бірлік)** | `pytest` | Жеке функциялар, модельдер, есептеу логикасы | 70% |
| **Integration (Интеграция)** | `pytest` | Дерекқормен және API-мен байланыс | 20% |
| **E2E (UI)** | `Playwright` | Пайдаланушының браузердегі әрекеттері | 10% |
| **Жүктеме (Load)** | `k6` / `Locust` | 50-100 пайдаланушы бір уақытта кіргенде | 1 рет (іске қосар алдында) |
| **API** | `Hoppscotch` / `Bruno` | Backend API-дің дұрыс жауап қайтаруы | CI-де автоматты |

**Орта (Environment):** Барлық тесттер GitHub Actions арқылы CI-де іске қосылады.

## 2. Тест деректері (Test Data)

Тестілеу кезінде нақты клиенттердің деректерін қолдануға тыйым салынады.
- **Fixtures (pytest):** Жасанды деректер жасалады (мысалы: "Алма", 500₸, 10 дана).
- **Faker кітапханасы:** Кездейсоқ жалған есімдер мен телефондар.
- **Дерекқорды тазалау:** Әр тесттен кейін автоматты тазалау (Rollback).

## 3. Мониторинг (Uptime Kuma)

Демо-стендтің жұмысын бақылау үшін Docker-де Uptime Kuma көтерілді.
- 60 секунд сайын сайтқа сұраныс жіберіп, құласа Telegram-ға хабарлайды.
